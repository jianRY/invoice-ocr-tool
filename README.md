# 发票识别汇总工具（Invoice OCR Tool）

把一堆票据（拍照 / 扫描 / 电子发票截图 / PDF）丢进一个文件夹，双击运行，自动识别并汇总成 Excel 表格。

> **本地离线 OCR，文件不出本机**。基于 [RapidOCR](https://github.com/RapidAI/RapidOCR)（ONNX Runtime），无需联网、不调用任何云端接口。

## 它能做什么

1. **选文件夹** → 自动识别其中全部票据
2. **PDF 自动转图片** → 文件夹里有 PDF 就先逐页转成 JPG（`原文件名_页码.jpg`）再识别，
   并新建「处理后」文件夹把转换结果与原有图片放在一起，后续结果都落在里面；
   如果全是图片则完全跳过这一步，行为与旧版一致
3. **自动归档** → 识别失败的图片复制到工作目录下的「未识别」子文件夹（没有就新建），原图保留不动
4. **导出 Excel** → 在工作目录生成 `发票识别汇总.xlsx`，含两张表：
   - **票据汇总**：文件名、发票号码、开票日期、购买方、销售方、项目数、项目金额合计、价税合计
   - **明细**：一个项目一行 —— 项目名称、数量、项目金额、价税合计

界面纯中文，带进度条与结果表格，识别失败的票据以红色标出。

### PDF 处理的三种情形

| 文件夹内容 | 行为 |
| --- | --- |
| 全是图片 | 跳过 PDF 步骤，直接识别（Excel 就在原文件夹） |
| 全是 PDF | 新建「处理后」文件夹 → 逐页转 JPG → 在「处理后」里识别与导出 |
| PDF + 图片混装 | 新建「处理后」→ PDF 转出的页图 + 原有图片一起复制进去 → 在「处理后」里识别与导出 |

- 原 PDF 保留在原文件夹，不删除、不移动
- 重复运行幂等：同名产物已存在就跳过，不会生成重复副本
- 加密 / 损坏的 PDF 会被单独挑出，复制到「处理后\未识别」并给出原因
- 界面上有「自动把 PDF 转成图片」开关（默认开启），需要时可取消勾选

### 支持的票据类型

- 增值税电子普通发票（数电票）
- 全国通用电子统一票据（医院电子票据）
- 财政医疗收费票据（含明细页）
- 药房销售小票、陪护费发票等常见票种

### 识别判定规则

发票号码、价税合计、明细项目**三者缺一**即判为「未识别」，图片复制到「未识别」文件夹。多页票据（如住院费用清单附件页）按单张图片处理，附件页通常会被归入「未识别」，建议人工补录。

## 使用步骤

1. 把所有票据（图片、PDF 可以混放）放进同一个文件夹
2. 双击运行 `InvoiceOcrTool.exe`（单文件版）或开始菜单里的「发票识别汇总工具」（安装版）
3. 点「浏览…」选中该文件夹，点「开始识别」
4. 有 PDF 时会先转成图片（进度条显示"准备文件…"），随后自动进入 OCR
5. 等待进度条走完，完成后会弹出统计（成功 / 未识别张数、PDF 转换情况、价税合计）
6. 点「打开所在文件夹」查看结果（有 PDF 时为「处理后」文件夹）：
   - `发票识别汇总.xlsx` —— 汇总表
   - `未识别\` —— 需要人工处理的图片或转换失败的 PDF

> 首次运行单文件版会有 5~10 秒解压等待，属正常现象；之后启动更快。

## 识别效果（真实样本实测）

用 62 张真实票据图片（含 30 张医院门诊票、7 张药房票、住院发票及财政票据明细页）测试：

- **58 / 62 张识别成功**，4 张失败的是住院费用清单附件页（预期行为，本就该归入「未识别」）
- **成功票据的价税合计 50 / 50 与人工核对结果完全一致**

## 从源码运行

```bash
pip install rapidocr_onnxruntime onnxruntime openpyxl pillow pymupdf
python app.py
```

源码结构：

| 文件 | 职责 |
| --- | --- |
| `app.py` | Tkinter GUI 主程序，含 `VERSION` 版本常量 |
| `pdf_convert.py` | PDF 前置转换：判断目录是否需要转换、渲染页图、复制原图、归置失败文件 |
| `parser.py` | OCR 结果解析：按列头坐标定位金额 / 数量列，按行聚类提取明细 |
| `excel_out.py` | 导出「票据汇总 + 明细」双表 Excel |
| `installer.iss` | Inno Setup 安装包脚本（由 `release.py` 调用编译） |
| `release.py` | 一键发版：打包 → 自检 → 签名 → 安装版 → 提交推送 → 建 Release → 更新展示页 |
| `tests/test_pdf_convert.py` | PDF 转换的场景测试（现场合成样本，36 项断言，改动该功能后先跑它） |
| `docs/index.html` | 静态展示页（GitHub Pages），发版时自动更新版本号与下载链接 |
| `deploy/update_site.sh` | 服务器侧脚本：定时把最新展示页与 exe 同步到自己的站点 |

## 一键发版

```bash
# 自动递增版本号并发布
python release.py --bump patch     # 小改 / 修 bug
python release.py --bump minor     # 新增功能
python release.py --bump major     # 大改版

# 只本地打包 + 签名，不碰 git / 远端（安全自测）
python release.py --dry-run
```

脚本会依次完成：打包单文件版与目录版 → **用产物跑 PDF 自检** → 签名 → 编译安装版 → 签名
→ git commit / tag / push → 建 GitHub Release 并上传两个 exe → 重新生成 `docs/index.html` → 推送。

**约定：本工具每次有改动都会自动发布新版本**，并同步更新展示页。
